# SatAPRS-Go

Go + Wails 桌面端 APRS 收发终端，首版面向 Windows 10/11 x64。

## 功能

- AX.25 UI 帧封装、FCS 校验、HDLC 位填充与 1200 bps Bell 202 AFSK 音频生成。
- 分别选择录音设备和播放设备，采集 48 kHz 单声道音频；使用 AFSK、NRZI、HDLC 与 FCS 流程尝试解码接收帧。
- 音频瀑布图使用 8192 点 Hann 窗 FFT、2048 个全频带计算频段，在 48 kHz 采样率下每段约 11.7 Hz；采用 75% 重叠计算改善刷新平滑度。后端仍计算 0–24 kHz 音频频谱，界面将 0–4 kHz 接收音频频段铺满瀑布图，方便观察 APRS 的 1200/2200 Hz AFSK 音调；画面不显示曲线、刻度或网格。
- 监听按钮整合启动与停止；启动操作在后台执行，避免 Windows 音频驱动阻塞界面。若录音设备 12 秒内没有响应，会解除“正在启动”状态并显示超时原因。音频初始化失败后可通过监听按钮重试，也可在配置页的音频设置中重新扫描声卡。
- 可在配置页开启“启动时自动开启监听”，启用后软件启动时会自动打开选定录音设备并监听。该选项默认关闭。
- 对方呼号输入框。双击左侧通信监视日志旁已解码呼号列表中的呼号，即可填入对方呼号。
- 主界面提供固定 F1 至 F6 六条预设按钮，以可配置的消息备注名称显示：左键发送，右键编辑备注名称、消息正文和“发送时将目标呼号设为 CQ”选项，并自动保存设置。默认 F1=`CQ {CALL} {GRID}`、F2=`UR 5NN`、F3=`TU 73`，F4–F6 正文为空，用户可自行设置。F1 默认启用“发送时将目标呼号设为 CQ”，各预设可单独修改此选项。空白预设不会发射，会打开编辑窗。自定义消息与预设都支持 `{HisCall}` 变量引用对方呼号。
- 其他消息变量：`{CALL}`、`{QTH}`、`{GRID}`、`{UTC}`。
- PTT 可选 Hamlib Net Rigctl、VOX、串口 RTS、串口 DTR 或手动控制。配置页的“测试 PTT”采用开关式持续控制：点击开始发射，再次点击停止，最长 30 秒后自动释放；如果释放命令失败，会每秒重试并显示告警。Hamlib 通过 `rigctld` TCP 文本协议发送 `T 1` / `T 0`；PTT 开启后保持同一 TCP 控制连接，停止时在该连接内发送 `T 0`，保持期间不另行查询 PTT 状态，以避免部分后端因连接关闭/额外状态查询而提前解除。RTS/DTR 可配置 COM 端口与有效电平。
- 可配置本机呼号、SSID、QTH、Maidenhead 网格定位符和 APRS 路径；呼号支持 `N0CALL/5`、`N0CALL/QRP` 这类特殊后缀。数字后缀 `/5` 映射到 AX.25 SSID `-5`；文本后缀（例如 `/QRP`）作为本地呼号别名及消息模板变量保留，实际 RF 源地址仍使用基础呼号和数字 SSID，因为标准 AX.25 地址不能编码文本后缀。
- 主窗口为固定视口自适应布局。TX/RX 信息、通信监视日志和已解码呼号列表保留独立纵向滚动条，并自动定位至最新记录。固定界面文字不可选中，输入框和实时日志文字仍可选择/复制。
- 文件菜单可清空配置（恢复内置默认值）、导出 JSON 配置或导入配置。导入/导出使用 Wails 提供的操作系统原生打开文件/保存文件对话框，不使用浏览器上传或下载。声卡设置在保存时会应用新端点；如果之前正在监听，会自动重新启动监听。
- 顶部“保存”菜单可以选择将完整 TX/RX 日志写入单个 `all.txt`，或按月（`all-YYYY-MM.txt`）、按年（`all-YYYY.txt`）拆分保存；还可打开日志文件夹，或清空所有本应用生成的 TX/RX 日志文件。日志存放在系统用户配置目录下的 `SatAPRS-Go` 文件夹，记录 UTC 时间、方向、完整 TNC2 帧、状态和 AX.25 原始帧十六进制内容。
- APRS 路径内置默认值为 `RS0ISS,SGATE,WIDE2-1`。设置保存在系统用户配置目录下的 `SatAPRS-Go/settings.json`。旧版本配置文件中多余的卫星字段会被忽略。

## 音频监听排查

1. 在“配置 → 音频 / 声卡”中选择连接电台接收音频的录音设备。若使用 USB 声卡，请在 Windows 声音设置中确认其输入端未被禁用，采样率可使用 48 kHz。
2. 点击主窗口“开始监听”。成功启动后，状态栏应显示监听状态，音频瀑布图会随录音输入持续刷新。
3. 如果显示“尚未收到音频采样”，说明音频设备虽已启动，但系统尚未把数据交给程序。检查设备选择、Windows 麦克风隐私权限、音量设置以及电台音频线。
4. 如果有采样而电平长期接近 `-120 dBFS`，说明输入基本静音。调高电台音量或声卡录音电平，确认接收音频确实接入所选输入端。
5. 如果监听启动失败或等待超过 12 秒，界面会显示具体错误。直接点击顶部“配置”，进入“音频 / 声卡”标签后点击“重新扫描声卡”，再重新选择录音设备。程序会在监听启动时重试音频上下文初始化。
6. 瀑布图反映录音输入的频率分布，不等于 APRS 解码成功。解码列表只显示通过 AX.25 帧校验并成功解析的接收帧来源呼号。

## PTT 与发射

- Hamlib PTT 需要已经启动并监听 TCP 端口的 `rigctld`，默认地址为 `127.0.0.1:4532`。本程序不会自动启动 Hamlib，也不会自动改变电台频率。
- RTS/DTR 使用 Windows 串口控制线。请使用独立 USB 转串口设备，配置正确 COM 端口与高低有效电平，并避免其他软件同时占用该端口。
- VOX 依赖电台自身的 VOX 设置；手动模式不会切换电台 PTT。
- 首次发射前，请在低功率条件下验证电台的音频输入、PTT 触发与释放。PTT 释放错误需要立即检查电台状态。
- APRS 消息建议使用 ASCII 字符，单条正文最多 67 字节；消息内部的空格、连续空格及首尾空格都会原样保留。自定义消息与预设正文编辑框优先使用 WebView2 原生文本输入；如空格键未产生任何输入，则在按键释放时补插一个 ASCII 空格。目标呼号输入支持 `/5` 等数字后缀映射，以及 `/QRP` 等文本别名按基础呼号路由。

## 构建

需要 Go 1.23+、Wails v2、Windows WebView2 Runtime，以及 Wails 所需工具链和可用的 C 编译环境（Malgo 基于 miniaudio）。

Windows 快速构建：

```bat
build_windows.bat
```

手动构建：

```powershell
go mod tidy
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
wails build -platform windows/amd64 -o SatAPRS-Go.exe
```

可执行文件输出位置：`build/bin/SatAPRS-Go.exe`。GitHub Actions 工作流会运行协议核心测试并生成 Windows AMD64 构建工件。

## 界面操作

- 主窗口顶部“开始监听 / 停止监听”是同一个切换按钮。
- F1 至 F6 以备注名称按钮显示：左键发送对应消息，右键编辑备注名与消息正文；键盘发射快捷键只有 F1 至 F6。
- `{HisCall}` 会替换成当前“对方呼号”输入框的值。
- 已解码呼号列表与左侧通信监视日志并排显示，采用紧凑行列表；双击某一呼号即可将其填入“对方呼号”。TX/RX 信息区逐行合并显示解码与发送记录，三个实时日志区均可纵向滚动，但会自动回到最新内容。


## 监听崩溃诊断

如果点击“开始监听”后应用仍然异常退出，诊断日志会写入当前用户配置目录下的 `SatAPRS-Go/sataprs.log`。Windows 通常为 `%AppData%\SatAPRS-Go\sataprs.log`。日志记录音频上下文初始化、设备枚举、录音设备启动各阶段。若应用仍闪退，请将该日志一并提供。Go 层启动异常、录音回调异常和 APRS 解码线程异常会被捕获并显示；底层音频驱动引发的原生崩溃无法由 Go 的 `recover` 捕获，但日志可以帮助确认崩溃前最后成功到达的阶段。

## cgo 音频设备 ID 修复

对于手动选择的声卡，旧代码曾把 Go 内存中的 `malgo.DeviceID` 地址直接写入 Malgo 的设备配置。配置经过 cgo 进入 C 时会触发 `runtime error: argument of cgo function has Go pointer to unpinned Go pointer`。当前版本改用 `malgo.DeviceID.Pointer()` 创建 C 管理的设备 ID 副本，并在 `malgo.InitDevice` 返回后通过 `C.free` 释放；录音输入和播放输出都采用此方式。未选择具体设备时仍使用系统默认设备，不会创建额外的设备 ID 缓冲区。


## v4 双击呼号与瀑布图显示范围修复

- 恢复已解码呼号列表的事件委托双击处理，双击任一呼号会将它填入“对方呼号”并聚焦输入框。列表动态刷新不会丢失双击监听。
- 瀑布图仍使用后端 8192 点 FFT，但把 0–4 kHz 显示频段映射到整张画布，避免 APRS 的 1200/2200 Hz 音调在 0–24 kHz 全范围显示时只集中在最左侧。


## v5 原生文件操作

- `文件 → 导出配置…` 调用系统原生“另存为”对话框并导出 JSON 配置。
- `文件 → 导入配置…` 调用系统原生文件选择器，所选 JSON 配置通过后端读取、校验并应用。前端不使用浏览器文件上传控件或 Blob 下载。
- `保存 → 打开日志文件夹` 在 Windows 文件资源管理器中打开应用配置与日志所在目录；macOS/Linux 分别使用系统默认文件管理器打开。


## v6 PTT 与特殊呼号修复

- 全局固定字号统一在 v5 基础上增加 2px。
- 配置对话框点击对话框以外的遮罩区域不会关闭，需使用关闭/取消按钮或保存按钮操作。
- 测试 PTT 以 `T 1` 启动持续发射，再次点击发送 `T 0`；30 秒到期自动停止，释放失败时每秒重试。测试 PTT 持续期间会阻止正常 APRS 发射，并在关闭应用时尝试释放。
- 本机呼号接受 `N0CALL/5`、`N0CALL/QRP` 等后缀；数字后缀映射为 SSID，文本后缀只保存在本机标识/模板中，不会伪装成可被 AX.25 地址承载的 RF 呼号。
- APRS 消息正文不会被自动 trim，空格可用于消息格式化；示例台站和测试数据使用虚拟 `N0CALL`、`N1TEST` 等占位符。

## v7 界面精简与日志换行

- 移除 TX/RX、LOG、APRS、RX 等面板标题前的文字徽标，保留清晰的区域标题。
- 删除 APRS 位置帧发送入口以及桌面端对应的 `SendPosition` 后端方法。
- 移除界面中的双击操作提示文字；双击已解码呼号填入目标呼号的功能仍保留。
- 消息收发区不再显示变量说明，仅在编辑预设消息时展示可用变量提示。
- TX/RX 信息与通信监视日志正文根据窗口宽度自动换行，避免窄窗口下被单行省略号截断。

## v9 rigctld/PTT 诊断与消息空格输入

- “Hamlib rigctld”设置页现在直接显示最近一次连接/PTT 测试详情，包括端点、发送的命令、rigctld 响应和 PTT 状态查询结果；不再只依赖诊断日志。
- Hamlib 固定使用通用 PTT 命令 `T 1`；测试与正常 APRS 发射保持同一 TCP 控制会话，停止时发送 `T 0`。配置页不再提供 `T 1`/`T 2`/`T 3` 类型选择。
- PTT 测试发送所选开启命令，然后在后台通过 `t` 查询状态用于诊断。状态查询返回 PTT=0 或查询失败时不会自动发送 `T 0`，不会因此中断测试；状态仅用于展示诊断信息，实际解除由用户再次点击或 30 秒安全超时完成。
- 测试 PTT 持续时间上限仍为 30 秒，支持再次点击停止；释放失败时自动重试。
- 自定义 APRS 消息和预设消息编辑框使用原生空格输入，并在 WebView2 未插入字符时提供按键释放后补插的兼容机制；消息正文中的内部空格、重复空格以及首尾空格由 APRS 编码链路原样保留。


## v10 PTT 持续控制修复

- 修复 PTT 测试在 `rigctld` 返回 `PTT=0` 时立即发送 `T 0` 的问题。现在成功收到启动命令响应后立即进入持续测试状态；后台状态查询仅用于诊断，不会成为维持 PTT 的门控条件。
- 移除测试 PTT 的确认弹窗，点击即发送开启命令，再次点击即发送解除命令。30 秒自动释放和释放失败后的自动重试继续保留。
- 状态查询仍报告接收时，配置页会显示警告并让测试继续保持开启，不再声称已触发实际射频发射；如电台仍未进入发射，应继续检查 rigctld 后端/电台 PTT 路由、CAT 连接和电台设置。


## v11 修复说明

- Hamlib PTT 在测试和实际 APRS 发射时使用持久 TCP 会话：启动命令与释放命令通过同一连接发送；保持期间不发起额外的 `t` 状态查询。
- PTT 测试回归测试确认，应用固定使用通用 `T 1`，手动停止或 30 秒超时发送 `T 0`；模拟 rigctld 测试要求启停命令复用同一连接。
- 预设正文与自定义消息输入框优先使用原生输入；只有检测到空格未写入值且光标未移动时，才在 `keyup` 阶段补插 ASCII 空格。

## v14 消息空格输入修复

- 为自定义 APRS 消息与预设消息正文编辑框分别绑定物理空格键处理，不再依赖 `keyup` 时比较值和光标是否变化。针对部分 Windows 输入法把空格键报告为 `key="Process"` 的情况，优先使用物理按键 `code=Space` 识别并插入 ASCII 空格。
- 两个输入框均增加“插入空格”按钮，始终在当前光标/选择位置插入一个普通 ASCII 空格，作为不依赖输入法键盘事件的备用方式。
- 浏览器端针对性测试在 Chromium 页面中通过浏览器键盘分发分别验证自定义消息与预设正文可输入 `TEST MSG`；这不是 Windows WebView2/实体键盘实测，实际 Windows 环境仍应确认当前输入法组合。
